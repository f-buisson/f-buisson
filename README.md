## Featured open-source work

### [OpenRetailSchema](https://github.com/f-buisson/OpenRetailSchema)

**Open, vendor-neutral retail data models and an extensible foundation for POS integrations.**

[![License: Apache 2.0](https://img.shields.io/badge/License-Apache%202.0-blue.svg)](https://github.com/f-buisson/OpenRetailSchema/blob/main/LICENSE)
[![Status: Early development](https://img.shields.io/badge/Status-Early%20development-orange.svg)](https://github.com/f-buisson/OpenRetailSchema)
[![Contributions welcome](https://img.shields.io/badge/Contributions-welcome-brightgreen.svg)](https://github.com/f-buisson/OpenRetailSchema/blob/main/CONTRIBUTING.md)

OpenRetailSchema is designed to let applications integrate with multiple POS systems without rebuilding the same data model for every vendor.

**Current focus**

- canonical schemas for retail data;
- explicit connector contracts and capability declarations;
- provenance-preserving normalization;
- generic CSV imports and reproducible fixtures;
- privacy-safe, synthetic test data;
- reusable foundations for analytics, planning and retail automation.

**Integration evidence:** an authorized Loyverse personal-token catalog integration has been tested in a separate F-Buisson product. The OpenRetailSchema connector itself is still experimental and is not presented as live-certified yet.

[Roadmap](https://github.com/f-buisson/OpenRetailSchema/blob/main/docs/ROADMAP.md) ·
[POS integration registry](https://github.com/f-buisson/OpenRetailSchema/blob/main/docs/POS_INTEGRATIONS.md) ·
[Contributing](https://github.com/f-buisson/OpenRetailSchema/blob/main/CONTRIBUTING.md)

> **Contributors wanted:** public API documentation, verified POS capabilities, schema reviews and fabricated sample payloads are welcome. Please never share credentials, tokens or real customer/store data.

## How I build

- **Start from real field problems** — solve operational needs before adding features.
- **Keep systems understandable** — important outputs and decisions should be explainable.
- **Keep humans in control** — automate repetitive work without removing managerial judgment.
- **Minimize training** — workflows should be clear enough to use with minimal onboarding.
- **Reuse integration work** — shared foundations should reduce duplicated POS-specific development.

## Français

<summary><strong>Présentation en français</strong></summary>

<br>

**F-Buisson** développe des logiciels métier pour le commerce, une infrastructure ouverte d’interopérabilité POS et des projets de R&D appliquée.

Le projet open source principal est **[OpenRetailSchema](https://github.com/f-buisson/OpenRetailSchema)** : une couche d'interopérabilité ouverte destinée à normaliser les données issues de différents logiciels de caisse / POS afin qu'une intégration puisse être réutilisée par plusieurs applications.

### Produits

- **Alertarif** — surveillance des prix, promotions, marges et qualité des données.
- **PlanCaisse** — planification des équipes caisse à partir des besoins réels et des contraintes opérationnelles.
- **PlanFlux** — suivi des renforts réellement effectués entre services.

### OpenRetailSchema

Le projet est en développement précoce. Une intégration catalogue Loyverse via jeton personnel autorisé a déjà été testée dans un autre produit F-Buisson, mais le connecteur OpenRetailSchema lui-même reste expérimental et n'est pas encore présenté comme certifié en conditions réelles.

Les contributions sont bienvenues, notamment pour la documentation d'API POS, les capacités vérifiées, les revues de schémas et les exemples synthétiques. Aucun identifiant, jeton ni donnée réelle de magasin ne doit être partagé.

### R&D publique
